## Why

Backend debugging currently relies on direct tRPC endpoint calls and ad-hoc tools, which slows down verification when procedures evolve. We need a built-in, low-overhead panel so developers can inspect and invoke procedures quickly in local and staging environments.

## What Changes

- Add a backend-served `GET /trpc-panel` debug page generated by `trpc-panel`.
- Introduce a dedicated backend module for tRPC panel responsibilities (controller, service, config).
- Add environment-driven safety controls so panel is disabled by default in production.
- Add unit and e2e tests covering enabled/disabled behavior and URL resolution.
- Add backend runtime documentation for new environment flags and endpoint usage.

## Capabilities

### New Capabilities
- `backend-trpc-panel`: Serve a built-in tRPC debugging panel endpoint with production-safe defaults and explicit configuration controls.

### Modified Capabilities
- None.

## Impact

- Affected code: `apps/backend` module registration, new `trpc-panel` module files, backend tests, and backend README.
- API surface: Adds `GET /trpc-panel` endpoint (debug-focused, environment-gated).
- Dependencies: Adds `trpc-panel` package in `apps/backend/package.json`.
- Operational behavior: New env flags `TRPC_PANEL_ENABLED` and `TRPC_PANEL_TRPC_URL` influence endpoint availability and target URL.
